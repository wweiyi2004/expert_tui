# 宠物包制作提示词（给其他 agent）

> 把下面整段交给负责做宠物的 agent，`<角色>` 处换成目标角色或形象描述。

---

你要为 Expert 终端（TUI）的启动页做一个像素宠物包，角色是：**<角色>**。产物是一个 JSON 文件，以及生成它的脚本。

## 1. 先读这些

- `design/tui/pet/README.md`：宠物包字段说明。
- `tool/build_simple_megumin.py`：默认宠物惠惠的生成脚本，照它的结构写。
- `next/tui/src/pet.rs`：加载、校验、播放逻辑，以代码为准。

## 2. 终端会怎么显示

- 启动页宠物最大占 **40 列 × 24 行**。每个字符格用 `▀` / `▄` 画上下两个像素，所以显示区域约等于 40×48 像素。窄窗口下会缩到 20 列 × 6 行。
- 源图按**最近邻**缩放，等比放进上面的区域，不做平滑。小于 1 像素的细节会直接丢失或闪烁。
- 透明像素露出终端自己的背景，深色和浅色背景都可能出现。轮廓要用深色描边，不能依赖背景色来衬托。
- 终端不支持真彩色时，颜色会映射到 xterm 256 色。相近的颜色可能并成同一个，配色时要拉开明度差。

**由此得出的画法：**
- 推荐底稿 **32×40**，所有像素放大 2 倍输出成 **64×80**（宽高比 4:5，和显示区域一致）。所有帧尺寸必须相同，上限 256×256。
- 只用大块平涂和 1 像素描边，不要渐变、抖动、纹理或单像素噪点。
- 调色板控制在 8–12 色：描边 1 色，主体 4–6 色，特效 2–3 色。
- 剪影要一眼认得出来。角色最有辨识度的 2–3 个特征（标志性的帽子、武器、发型、配色）要夸张画出来。惠惠早期版本就是因为法杖成了直棍、帽徽丢了，看起来像普通女巫。
- 脸至少留 3 像素高的眼睛区域，嘴用 1–2 像素。脸下方不要放大块深色，否则缩小后会像胡子或面罩。

## 3. 文件格式

```json
{
 "name": "显示名",
 "palette": {"o": "#30242e", "s": "#f2d1b7"},
 "frames": {"idle": ["....", "..."], "...": []},
 "idle": {"frames": [["idle", 900], ["idle_breath", 900]], "blink": "blink"},
 "clicks": ["intro", "special"],
 "actions": [
  {"id": "intro", "frames": [["pose", 240], ["pose_alt", 240]], "duration": 1600,
   "quotes": [[0, "「台词」"]]},
  {"id": "special", "frames": [["a", 200], ["b", 450]], "next": "rest", "reduced": "rest",
   "quotes": [[0, "「前半句」"], [400, "「后半句」"]]},
  {"id": "rest", "frames": [["tired", 0]], "hold": true,
   "quotes": [[0, "「累了」"]], "release_quote": "「再来」"}
 ],
 "quote_ms": 2500
}
```

加载时会做以下校验，任何一条不满足都会被拒绝，并改用惠惠：
- 调色板的键是单个可见 ASCII 字符，不能是 `.`（`.` 固定表示透明）；值必须是 `#RRGGBB`。
- 每一帧的行数和每行长度都一致，只能出现 `.` 和调色板里的键。
- `idle.frames` 不能为空。它的第一帧决定宠物尺寸，也是减少动态效果时唯一显示的帧。
- `idle`、`blink`、`clicks`、`next`、`reduced` 引用的帧和动作都必须存在。
- 非 `hold` 的动作，帧时长之和（或 `duration`）必须大于 0。

播放规则：
- 每次点击按 `clicks` 的顺序依次启动动作，循环使用。动作播放期间点击无效；`hold` 动作要再点一次才会回到待机，此时显示 `release_quote`。
- 没有 `duration` 时，帧序列播放一遍后停在最后一帧，播完即结束；有 `duration` 时循环播放直到该时长。动作结束后接 `next`，没有 `next` 就回到待机。
- `quotes` 按开始时间显示最近开始的一句，从动作开始起最多显示 `quote_ms` 毫秒。每句台词不超过 18 个汉字，用「」括起来。
- 眨眼帧每 3–6 秒出现一次，停留 150ms；减少动态效果时不眨眼。

## 4. 动作要求

至少画这些帧：
- **待机** `idle`，以及**呼吸** `idle_breath`：上半身下沉 1 像素，脚保持不动。
- **眨眼** `blink`：只改眼睛。
- **至少两个点击动作**，其中一个要有完整的起承转合：蓄力 → 高潮 → 收尾 / 结束姿势。高潮帧可以用特效色占据画面一侧。
- 每个动作都要有足够明显的姿势变化，至少移动 3–4 像素，否则缩小后看不出在动。
- 如果有闪烁、爆炸之类的强烈特效，给它配一个 `reduced` 替代动作。

## 5. 工作流程

1. 写 `tool/build_<名称>_pet.py`。参照惠惠的脚本：用文本行手工摆放各部件，提供 `stamp`、`rect`、`line` 等辅助函数，用参数切换表情和姿势，避免整帧复制。输出 JSON 时一律带 `encoding='utf-8'` 和 `ensure_ascii=False`，Windows 默认编码会把中文写坏。
2. 运行脚本，输出到 `design/tui/pet/<名称>.json`。
3. **自己检查**：用 Pillow 把所有帧按原尺寸放大渲染成一张总览图；再按 38×24 格、每格上下两像素做一次最近邻缩放，模拟终端效果，分别放在深色和浅色底上看。肉眼确认角色认得出来、动作看得出变化，再继续。
4. 安装测试：复制到配置目录的 `pets/<名称>.json`（Windows 下是 `%APPDATA%\expert-chat\pets\`），在 TUI 里运行 `/pet <名称>`。如果包不合法，会直接提示原因。
5. 不要修改 `megumin.json`、`pet.rs`，也不要改校验规则。格式不够用时，先提出需要的字段，不要自行扩展。

## 6. 交付

- 生成脚本、JSON，以及总览预览图（只用于查看，不需要提交）。
- 一句话说明每个动作的内容和总时长，列出调色板中每种颜色的用途。
- 说明你自己检查时发现的不足，比如哪一帧缩小后细节丢失。
